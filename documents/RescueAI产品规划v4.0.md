# RescueAI 产品规划 v4.0

> 基于现有平台功能与 v3.0 视觉设计体系的统一产品规划
> 编制日期: 2026-08-29 | 状态: 待评审

---

## 1. 规划背景：现状盘点

### 1.1 三条产品线现状

| 产品线 | 载体 | 状态 | 承担角色 |
|--------|------|------|----------|
| **演示线** | 单文件指挥中心 (`backend/Qwen 初版/代码1.2-ai.html` + `ai_proxy.py`:8010) + 实时社情层 (`live_feed.py`:8012) | ✅ 已验收 | 复赛/决赛主演示载体，核心 AI 能力全部在此验证 |
| **在线线** | Vercel 部署 (`deploy/`，与单文件字节级同构) | ✅ 已上线 | 评委/公众随时可访问的在线版 |
| **平台线** | Vue3 + FastAPI 标准平台 (`frontend/` + `backend/app/`) | 🚧 建设中 | 长期产品化方向，v2.7 已有 11 个视图，v3.0 文档已定稿 |

### 1.2 已验证的核心能力（演示线，8 项）

1. **双源感知**: ICL 地震预警 × 微博社情瀑布流（weibo-cli 真实通道）
2. **AI 灾情简报**: Qwen3.8-Max 生成 ≤200 字简报
3. **P0-P3 救援优先级**: 按倒塌形态、失联规模排序
4. **社情热力图**: 帖量、损毁类型、情感时间线（ovSocial 叠加层）
5. **空中搜索**: 无人机扫描与遥测接口预留
6. **余震联动**: 强余震自动暂停作业
7. **历史事件回测**: 2025 缅甸地震四幕重演剧场（真实时间轴压缩回放）
8. **三级降级保险丝**: 真 AI → 预录兜底 → 纯仿真（`?sim=1`）

### 1.3 平台线现状（v2.7 → v3.0 差距）

- v2.7: 9+ 个一级视图（Dashboard / DisasterMap / DisasterReport / DisasterList / ResourceCenter / VolunteerManage / TrackedPersons / AssessmentReport / AIAssistant / UserManage），Element Plus 视觉
- v3.0 文档已定稿但未实施: 5 模块导航、三步上报、AI 调度推荐算法、Tailwind 新视觉体系
- 最小社情合入已定案: `app/services/social/`（PlatformAdapter）+ SocialPost 模型 + `/api/v1/social` 四端点 + 52 条种子数据

### 1.4 核心问题（不变）

地震后黄金 72 小时的**信息黑洞**：官方通报静默期（缅甸首报滞后社媒约 5 小时）、灾情信息碎片化散落社媒、"哪里最重、先救哪里、怎么过去"缺乏系统性答案。

## 2. 产品定位与设计原则

### 2.1 一句话定位

> **地震黄金 72 小时 AI 辅助决策系统（数字孪生推演）——辅助专业判断，不替代专业判断。**

### 2.2 五条产品级设计原则（全线约束）

| # | 原则 | 来源 | 约束范围 |
|---|------|------|----------|
| 1 | **单地图架构**: 所有空间信息叠加在主数字孪生地图上，禁止双地图并存 | 已定架构原则 | 所有新功能 UI 设计与评审 |
| 2 | **辅助不替代**: AI 输出必须附推理依据与置信度，保留人工干预点 | 产品定位 | 所有 AI 功能 |
| 3 | **降级可用**: 任何 AI/网络依赖必须有兜底路径（真 AI → 缓存/预录 → 纯仿真） | 三级保险丝已验证 | 所有在线依赖 |
| 4 | **口径强制**: 震级双口径（CENC 7.9 / USGS Mw7.7）等事实数据以源代码验证为准 | 口径决策 | 所有文档、Prompt、UI 文案 |
| 5 | **隐私优先**: 社情数据剥离昵称/UID，受困者位置仅授权可见 | 合规规范 | 感知层与人员管理 |

### 2.3 目标用户（沿用 v3.0 画像，明确优先级）

| 优先级 | 角色 | 核心场景 | 本期投入 |
|--------|------|----------|----------|
| P0 | 指挥员 | 指挥中心大屏 + 桌面端全局态势与决策 | 主力打磨 |
| P1 | 现场救援队 | 移动端任务接收、上报、导航 | v4.x 启动 |
| P2 | 数据分析师 | 复盘报告、趋势预测 | 复用回测能力 |
| P3 | 医疗/志愿者协调 | 分诊、排班 | 决赛后规划 |

## 3. 功能规划：四层能力栈

以"感知 → 认知 → 行动 → 复盘"重组全部功能，明确每项能力的当前状态与目标状态。

```
┌────────────────────────────────────────────────────────┐
│  ④ 复盘层  历史回测 · 评估报告 · 演练模式              │
├────────────────────────────────────────────────────────┤
│  ③ 行动层  优先级队列 · 智能调度 · 空中搜索 · 人员管理 │
├────────────────────────────────────────────────────────┤
│  ② 认知层  AI简报 · 优先级推荐 · 风险预测 · 余震联动        │
├────────────────────────────────────────────────────────┤
│  ① 感知层  ICL/USGS预警 · 多平台社情 · 现场上报        │
└────────────────────────────────────────────────────────┘
```

### 3.1 感知层

| 能力 | 现状 | 规划 |
|------|------|------|
| 地震预警接入 | ICL 快照 + USGS 实时（Vercel api 已验证） | 平台线接入同源数据，统一为 `SeismicEvent` 模型；CENC/USGS 双口径展示 |
| 微博社情 | live_feed.py 真实通道 + 降级链 | 迁入 PlatformAdapter（weibo_adapter 已定案），去重与隐私剥离下沉到服务层 |
| 多平台扩展 | 抖音/小红书占位 | 决赛后按官方 API 合规规范逐个接入，不做爬虫 |
| 现场上报 | v2.7 七步表单 | 落地 v3.0 三步极速上报（定位 → 拍照 AI 预填 → 确认），图像识别自动判类 |

### 3.2 认知层

| 能力 | 现状 | 规划 |
|------|------|------|
| AI 灾情简报 | 演示线已验证（≤200 字） | 平台化为 `/api/v1/ai/brief`，支持定时自动生成日报 |
| 优先级推荐 | P0-P3 规则排序已验证 | 升级为 AIRecommendation 模型：内容 + 置信度 + 推理依据 + 建议操作，支持采纳/忽略闭环 |
| 余震联动 | 强余震自动暂停作业已验证 | 扩展为风险区域图层（余震概率影响调度评分） |

### 3.3 行动层

| 能力 | 现状 | 规划 |
|------|------|------|
| 救援队派遣 | 演示线五阶段流程（开进/现场勘察/语音联络/破拆支护/医疗移交） | 平台化为 DispatchTask + RescueTeam 模型，状态机对齐五阶段 |
| 智能调度 | v3.0 文档定稿（加权评分：距离/库存/风险） | 实施 AI 调度建议卡（方案 A/B + ETA + 风险），保留三个人工干预点 |
| 空中搜索 | 无人机扫描接口预留 | 维持接口预留，决赛后接遥测数据；地图上作为独立图层 |
| 人员管理 | v2.7 Volunteer/TrackedPersons 视图 | 落地 v3.0 数据模型（TrappedPerson 四色分诊、技能匹配） |

### 3.4 复盘层

| 能力 | 现状 | 规划 |
|------|------|------|
| 历史回测 | 缅甸四幕重演剧场（演示线核心资产） | **提炼为平台"演练模式"**: 任意历史事件时间轴压缩回放，用于培训与预案演练 |
| 评估报告 | v2.7 AssessmentReport 视图 | 接入 AI 自动生成，含趋势对比与资源消耗分析 |

## 4. 视觉设计规划

### 4.1 双主题策略（在 v3.0 规范基础上明确分工）

v3.0 视觉规范（"冷静·清晰·可信"）保持不变，本次规划明确**两种视觉语境的分工**：

| 语境 | 主题 | 适用页面 | 理由 |
|------|------|----------|------|
| **指挥语境** | 深色主题为默认 | 指挥大屏、态势地图、重演剧场 | 演示线深色指挥中心风格已验证，大屏/地图场景降低眩光、突出预警色 |
| **管理语境** | 浅色主题为默认 | 灾情列表、资源中心、人员管理、设置 | 表单/表格密集页面浅色可读性更好 |

两种语境共用同一套 Design Tokens，通过 `.dark` 类切换，用户可手动覆盖。

### 4.2 色彩体系（继承 v3.0，补充映射规则）

- **品牌三色**: Primary Blue `#2563EB` / Secondary Teal `#0D9488` / Accent Purple `#7C3AED`
- **AI 专属视觉**: 所有 AI 产出（简报、建议卡、研判结果）统一使用紫→蓝渐变 + AI 徽标，与人工录入数据明确区分——这是"辅助不替代"原则的视觉表达
- **优先级色**: 平台线 P0-P4 五级（`#DC2626`/`#EA580C`/`#CA8A04`/`#2563EB`/`#059669`）；演示线 P0-P3 四级在合入时映射到前四档
- **红色纪律**: 红色仅用于 P0 危急与真正紧急预警，禁止装饰性使用

### 4.3 单地图视觉规范

- 主地图为唯一空间画布，全部空间信息以**图层**呈现（灾情/队伍/资源/受困者/风险区/路况/医疗/避难所 8 层，沿用 v3.0 图层清单）
- 社情热力图作为 ovSocial 叠加层合入主地图（已验证方案），保持空间一致性
- 迷你地图仅允许作为指挥大屏的"跳转入口预览"，不承载操作

### 4.4 组件与动效

- 组件规范沿用 v3.0（按钮/卡片/表单/标签/聊天气泡），技术栈 Tailwind + Lucide + VueUse Motion
- 紧急脉冲动画（pulse）仅用于 P0 事件与余震预警
- 无障碍：WCAG AA 对比度、44px 触摸目标、快捷键（R 上报 / M 地图 / Space 暂停刷新）

## 5. 版本路线图

对齐已定案的分段合入决策（复赛最小层、决赛后全量）：

### v3.5 — 复赛冲刺（现在 → 2026-09-04 体验包到期前）

**原则：演示价值由演示线承载，平台线只做最小合入，不动已验收功能。**

- [x] 双演示载体维持现状（8010 + 8012）
- [x] Vercel 在线版三模式 E2E 通过
- [ ] 平台线最小社情合入验收：PlatformAdapter + `/api/v1/social` 四端点 + 种子回填
- [ ] 演示排演与答辩材料按口径规范终审

### v4.0 — 平台化并轨（决赛后，约 10 周，对齐 v3.0 实施五阶段）

**目标：演示线已验证的 8 项能力全部平台化，视觉切换到 v3.0 体系。**

- Phase 1-2 (W1-4): Design Tokens + Tailwind 主题 + 基础组件库（含深/浅双主题）
- Phase 3 (W5-6): 5 模块导航落地；Dashboard 改造为指挥大屏（深色）；单地图 + 8 图层
- Phase 4 (W7-8): 三步上报、AI 调度建议卡、WebSocket 实时推送、AI 简报/研判端点化
- Phase 5 (W9-10): 缅甸重演迁移为平台"演练模式"；E2E + 无障碍审查 + 性能达标（首屏 <2s, Lighthouse >85）
- 技术债清偿: `/api/v1/social/ingest` 补鉴权（上线前强制项）

### v4.5 — 能力扩展（v4.0 稳定后）

- 全量合入 `work buddy接力/` 补丁包（无人机/简报/决策等愿景 4-7），逐项验证后再合
- 多平台社情（抖音/小红书官方 API）
- 移动端现场救援队视图（P1 用户）
- 智能调度算法引入实时路况

### v5.0 — 远期方向（不承诺时间）

- AR 实景叠加（v3.0 已列为未来扩展）
- 多灾种扩展评估（当前坚持地震垂直深耕，扩展需单独立项论证）
- 传感器/卫星影像接入

### 版本收敛后的载体归宿

| 载体 | v4.0 后角色 |
|------|-------------|
| 单文件指挥中心 | 归档为"离线应急包"——无网环境下的最后兜底（契合降级原则），不再新增功能 |
| Vercel 在线版 | 切换为平台线的在线部署 |
| 标准平台 | 唯一主开发线 |

## 6. 非功能与合规要求

| 类别 | 要求 | 依据 |
|------|------|------|
| 可用性 | 三级降级链覆盖所有 AI/网络依赖；弱网场景实测 | 演示线已验证模式 |
| 安全 | social ingest 端点鉴权；DashScope Key 走环境变量，前端零 Key | 已知技术债 |
| 隐私 | 社情昵称/UID 剥离；受困者位置权限分级 | 数据合规说明 |
| 数据口径 | CENC 7.9 / USGS Mw7.7 双口径；伤亡数据标注通报时点（如"截至 3/29 晚通报 1,644 人"）；所有公开文案过源码验证 | 口径决策 |
| 数据来源 | 仅官方 API / 授权通道，不使用爬虫 | 合规规范 |

## 7. 成功指标

| 维度 | 指标 | 目标 |
|------|------|------|
| 决策效率 | 从预警到首条 AI 简报 | < 60s |

| 体验 | WCAG AA 对比度合规 | 100% 已验证组合 |

## 8. 风险与开放问题

1. **weibo-cli 体验包 2026-09-04 到期**: 到期后实时社情降级为 cache→mock，需推进官方通道正式认证（复赛前最高优先级外部依赖）
2. **`work buddy接力/` 补丁包未经首跑验证**: 维持决赛后逐项合入策略，禁止复赛前整包合入
3. **演示线与平台线双轨维护成本**: v4.0 完成前，任何新功能默认只进演示线或只进平台线，不双写
4. **多灾种扩展诱惑**: 坚持地震垂直定位，扩展提案一律进 v5.0 评估池
