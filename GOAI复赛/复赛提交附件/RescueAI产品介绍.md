## 一、问题：震后黄金 72 小时的「信息黑洞」

地震救援存活率随时间急剧下降，而恰恰在最宝贵的时间窗口内，信息供给是断裂的。

**存活率阶梯：** 震后 24 小时约 **80%** → 48 小时约 **50%** → 72 小时约 **30%**。

| 痛点 | 事实依据（2025-03-28 缅甸地震实测） |
|---|---|
| **官方通报沉默期** | 震后约 **5 分钟**社媒已在流传伤亡信息；官方首报 **03-28 19:15** 才发布——沉默约 **5 小时** |
| **灾情信息碎片化** | **53,340 条**中文微博散落呼救、损毁、谣言，无结构化、无坐标、无优先级 |
| **无系统化决策答案** | 「哪里最严重？先救哪里？路怎么走？」——三个指挥核心问题均无现成答案 |

**一个关键细节：** 首条涉震微博**早于主震发震时刻 1 分 46 秒**。社交媒体是比仪器台网更快的「第一传感器」，但今天没有任何系统把它接进救援指挥链路。

> **RescueAI 的思路：让 AI 把社媒上的每一句呼救，变成地图上的坐标和优先级。**

## 二、定位、用户与设计原则

### 2.1 一句话定位

> **地震黄金 72 小时 AI 辅助决策系统（数字孪生推演）——辅助专业判断，不替代专业判断。**

### 2.2 目标用户

| 优先级 | 用户 | 核心场景 |
|---|---|---|
| **P0** | 各级应急救援指挥部门 / 应急管理者 | 震后第一时间生成灾情简报、划定区域优先级、辅助调度决策 |
| **P1** | 一线救援队 | 获取目标坐标、安全进入路径、被困者状态与营救队列 |
| **P2** | 人道机构与公益组织 | 物资缺口估算、援助明细对齐、公益协作清单 |

### 2.3 五条产品级设计原则

| # | 原则 | 含义 |
|---|---|---|
| 1 | **单地图架构** | 所有空间信息叠加在主数字孪生地图上，禁止双地图并存 |
| 2 | **辅助不替代** | AI 输出必附推理依据与置信度，保留人工干预点 |
| 3 | **降级可用** | 任何 AI/网络依赖必有兜底路径（真 AI → 预录 → 纯仿真） |
| 4 | **口径强制** | 震级双口径等事实数据以源码验证为准，公开文案不夸大 |
| 5 | **隐私优先** | 社情数据剥离昵称/UID，受困者位置仅授权可见 |

## 五、Agent 能力与端到端任务链路（评审维度：真实行业场景与 Agent 能力）

### 5.1 端到端七步闭环

```
① 预警信号/地震检测 → ② 微博社媒监测 → ③ 噪声过滤（去重→辟谣→机器人→地理围栏）
→ ④ NLP 实体抽取（NER） → ⑤ 社情热力图 → ⑥ 优先级引擎 → ⑦ 无人机救援调度
```

检测到任何地震信号即立即启动社媒监测，七步在统一指挥界面逐段点亮、全程可追溯。

### 5.2 一条可验证的完整任务链路（实测时延）

以「缅甸地震 → 空投急需物资」为例，全链路真实可跑：

| 步骤 | 动作 | 实测 |
|---|---|---|
| 1 | ICL/USGS 预警触发，进入指挥态 | 开屏即现 |
| 2 | 社情瀑布流接入 + NER 聚合 | 曼德勒聚合 **12 帖** |
| 3 | AI 灾情简报自动生成 | **2.7s** 出稿 |
| 4 | 优先级引擎排序，产出 P0 区域 | 第一名 **曼德勒市区 16.4 分** |
| 5 | 指挥员**二次确认**派遣 | 人工确认点（WP10） |
| 6 | 五阶段救援推演（开进→现场勘察→语音联络→破拆支护→医疗移交） | 派遣→救出 **35.5s** |
| 7 | 物资空投 = 引擎第一名区域，附红会援助明细锚点 | 投送目标与引擎**一致** |

## 六、用户流程闭环与人工确认边界（评审维度：用户流程闭环）

**指挥员操作闭环（6 步）：** 看态势（双源+热力图）→ 读简报（AI 灾情简报）→ 定优先级（P0–P3 + 证据链）→ 派任务（派遣二次确认）→ 盯过程（五阶段 + 余震联动）→ 做复盘（回测剧场 + 评估）。

**人工确认边界（高风险场景强制）：**

| 环节 | 机制 | 边界声明 |
|---|---|---|
| **派遣救援** | 二次确认弹窗「确认派遣 · 推演」，取消则不派遣；确认后显示「✓ 已确认（人工）」徽标 | **最终决定权在现场指挥部**；`?sim=1` 下同样生效 |
| **上报指挥部** | 「上报现场指挥部」为**信息递交动作** | **批复权在人工**，系统不模拟批复结果 |
| **AI 输出** | 每条结论附原始微博/官方通报证据链与置信度 | 无匹配帖时如实显示「社情信号 ×0 · 依据官方通报」，**不编造** |
| **预测估算** | 展示不确定性区间 | 热力强度为模型推断，**不作为唯一决策依据** |

## 七、技术实现（评审维度：技术实现）

### 7.1 AI 层

| 项 | 实现 |
|---|---|
| 文本模型 | qwen3.8-max（简报/决策助手/优先级理由/余震参谋/喊话），超时 5s |
| 视觉模型 | qwen3.7-plus（航拍侦察研判），超时 20s |
| 本地代理 | `ai_proxy.py`（仅 Python 标准库，端口 8010，仅回环）：参数白名单 + 默认注入 `enable_thinking:false`；60s TTL / 200 条内存缓存；任何异常一律返回结构化 fallback |

### 7.2 数据管线（社情漏斗与误报控制）

**53,340** 原始 → 去重剔 12,743 → **40,595** → 关键词初筛 **9,617** → 抽样 100 → LLM 甄别 **100 次调用 / 0 失败** → 实质 **65** → 精选 **52**。

四层噪声过滤：L1 去重（bigram Jaccard>0.85）→ L2 辟谣关键词 → L3 机器人（#标签>5 或正文<5字）→ L4 地理围栏（距震中>300km 剔除）。

> **边界声明：** 四层漏斗为工程过滤规则，**不等于谣言查全率**；社情信号与官方通报交叉验证为最终防线，无社情匹配区域如实显示「社情信号 ×0 · 依据官方通报」，不编造。

### 7.3 可视化与扩展

- **可视化**：单文件 HTML + Canvas 2D + 内嵌 SVG，**零第三方图表库、零构建**，数据全内嵌（零 fetch）。
- **地图图层（5 层）**：热成像信号 / 激光雷达点云 / 设备定位信号 / 安全进入路径 / 社情感知。
- **真机预留**：`POST /drone/telemetry` 桩已预留大疆 Cloud API / MAVLink 转发位，真机接入即插即用。

| 场景 | 实测 |

### 8.4 回归矩阵

**10 个验收脚本、≈90 项断言全部通过**（verify-live / verify-ai / verify-t5 / verify-replay / t13 / t15 / t26 / t27 / verify-t25 / verify-mainrefactor）；回测剧场 **9 项真实事件口径逐项吻合**。

### 8.5 如实披露与边界（不夸大）

| 项 | 如实口径 |
|---|---|
| 损毁类型分类回测 | n=52，accuracy **0.5962**（macro F1 0.5270）；高支持度类别可用，小样本类不稳定 |

| 样本边界 | 样本量 52、单一历史事件、非独立测试集——**演示级口径，不构成泛化性能承诺** |
