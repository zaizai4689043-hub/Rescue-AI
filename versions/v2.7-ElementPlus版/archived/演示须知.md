## 第二幕「沙盘推演」（主仪表盘 · 约 3-4 分钟）
空中搜索 → 结构研判 → 派遣 → 五阶段救援 → AI 参谋，收尾 AI 复盘参谋：

1. **起飞**：点「启动空中搜索」，无人机全域扫描，被困人员逐个点亮（AI 自动生成优先级决策理由）。
2. **结构研判**：Qwen-VL 多模态输出四值（墙体匹配/承重构件/疑似空隙/结构完整度），可「换图重测」。
3. **派遣**：队列卡片一键派遣，五阶段状态机推进（开进→表面搜索→喊话联络→破拆支护→转运移出），阶段 2 可点击喊话实现语音联络秒回。
4. **余震联动**：手动「余震模拟」4.2 级不打断作业；强余震（mag≥5）自动暂停破拆支护约 3s 后恢复。
5. **收尾**：点「🧭 生成本次复盘」，AI 复盘参谋 ≤150 字总结「如果地震再来一次，AI 能做什么」（基调克制、致敬一线）。

## ICL 预警卡片与离线快照机制（①段「国内实时」）
- **位置**：重演剧场①段「监测告警」面板底部的青色小卡片，展示最近 5 条国内地震预警（地点/震级/烈度/时间，烈度按 1–5 级映射上色）。
- **定位（叙事红线）**：仅展示「当前国内预警能力」，与①段史实形成对照——2025-03-28 缅甸地震震中距中国边境 294km，超出 ICL 约 50km 响应半径，全球无预警发出。卡片内**不含**缅甸事件预警记录，①段既有文案锚点未改动。
- **数据链（降级链）**：前端 `GET /icl/warnings`（代理 300s 内存缓存，urllib 拉取上游、显式 10s 超时）→ 失败/超时/空数据 → 回落 `data/icl_warnings_snapshot.json` 快照并带 `offline:true`（标签切「离线快照数据」）→ 快照也失败 → 内嵌最小样例。前端再以内嵌 `ICL_OFFLINE` 作双保险。
- **快照**：`data/icl_warnings_snapshot.json`（含 meta 抓取时间/来源），是演示零外网依赖的保险；`?sim=1&replay=1` 直接用前端内嵌快照零请求渲染（不发 fetch）。
- **数据源**：成都高新减灾研究所（ICL），`mobile-new.chinaeew.cn/v1/earlywarnings`（免鉴权，须带 `start_at`/`updates` 参数）。

## 真机接入方式（预留接口，当前为仿真驱动）
单机遥测已按「真机可替换」设计预留，接入三步即可，无需改动画面逻辑：

1. **遥测帧格式（`DRONE_TELEMETRY_SCHEMA`，见前端 `代码1.2-ai.html` 注释块）**：
   ```json
   {"id":"无人机-01","x":520,"y":210,"heading":1,"battery":87,"mode":"search","payload":null}
   ```
   字段：`id` 机号 / `x`,`y` 地图坐标 / `heading` 航向 / `battery` 电量% / `mode` 模式 / `payload` 载荷透传。
2. **接入端点**：真机经 大疆 Cloud API / MAVLink 转发为上述帧，`POST /drone/telemetry`（现为 501 桩，接入时替换为解析并推送）；前端统一经 `applyTelemetry(frame)` 写入 `S.drone` 驱动画面。
3. **口播稿（一句话）**：「当前为数字孪生仿真驱动，同一遥测协议可直接替换为实机。」
