# STORY.md — RescueAI 黑客松路演 PPT

## ① 用户意图对齐

- **目标受众**：Physical AI Hackathon 评审，路演/评审场合。
- **核心目标**：讲完后评审相信——RescueAI 把社媒呼救转化为可行动的救援决策（坐标 + 优先级 + 路线），且已用真实数据完成验证；记住一句话"AI 不替代救援者，它做的只是把时间抢回来"。
- **PPT 长度**：10 页（Hero 页 3 页：封面、痛点、结束页；占 30%，符合 20-30%）。
- **视觉调性**：暗色指挥中心、琥珀警示、青色科技、数据密集、克制致哀。
- **内容边界**：必讲——三大问题（哪里最严重/先救哪里/路线规划）、七步产品路径、四层技术架构、真实数据验证。禁碰——不得说"社媒跑赢地震波"（用"社媒补充感知"）；不得说 M≥5.0 触发（任何地震信号）；微博 API 表述为"已预留接口"；ICL 须标注成都高新减灾研究所；死亡口径"截至3/29晚通报1,644人，持续更新中"。

## ② 页面布局骨架

- **总数与分章**：10 页。章一·问题（P1-P3），章二·产品（P4-P7），章三·技术与验证（P8-P9），章四·收束（P10）。
- **Hero 页**：P1 封面（hero）、P3 三大问题（hero）、P10 结束页（hero）。间隔合规。
- **rhythm 曲线**：P1 peak → P2 valley → P3 peak → P4 transition → P5 valley → P6 valley → P7 peak(视觉) → P8 valley → P9 valley → P10 peak。P5/P6 连续两页 valley 后由 P7 无人机视觉页打破。
- **非对称版式预算**：≥40% 用非对称——P2 巨型数字+洞察、P4 非对称流程链、P5 非对称双栏（60:40）、P6 左标题+右内容、P7 左大图+右侧文字、P8 非对称分层架构、P9 巨型数字+洞察。共 7 页非对称。
- **对称版式预算**：仅 P3 使用"全屏视觉+大标题"变体（居中金句）、P10 结束页居中金句。N卡片横排全篇 0 次。

## ④ 复赛新增四章 · 叙事衔接段（任务 #14，对应《RescueAI复赛方案.pptx》P7/P8/P11/P12）

> 口径说明：以下四章沿用 5 分钟路演口径与「辅助决策、不替代专业救援判断」定位；再生成命令：`.venv-ppt/bin/python .ppt_build/build_ppt.py outputs/rescueai_pitch/RescueAI复赛方案.pptx`（无参则仍生成初赛 11 页版），样式与初赛版同构。

- **Agent 架构（P7）**：核心能力讲完，用「感知→聚合→研判→决策→交付」一页流水线把 Agent 闭环说透——同一闭环支撑两幕演示载体（Qwen 初版主演示与建设中的标准平台），实时层由 live_feed 适配器按 mock / weibo 切换；三级降级是产品能力而非应急补丁。衔接句：「能力看完了，这页讲它们如何被同一个 Agent 串成闭环。」
- **工具调用（P8）**：一页表格如实标注六项工具与通道的接入状态——DashScope 文本、Qwen-VL 视觉、USGS ComCat / ICL 快照与 Playwright harness 已接入，无人机遥测接口已预留，weibo-cli 认证与订阅申请中；评委追问任一工具，答「状态即页上所示」。衔接句：「闭环靠工具落地，状态我们一个不藏。」
- **风险边界（P11）**：工程可靠性之后先讲「不做什么」——不自建爬虫只走官方通道、昵称与 UID 整列丢弃的脱敏管线、辅助决策不替代专业救援判断、社媒谣言四层过滤加交叉验证，外加震级双口径与死亡数字的口径红线管理；全部引自《数据来源与合规说明.md》。衔接句：「可靠性之外，我们还给自己画了红线。」
- **评测指标（P12）**：以《评测指标实测报告》浓缩版十条收尾（简报 ≈3.0s / 决策理由 8/8 / 漏斗 53,340→52 / `?sim=1` 零请求 / 10 脚本 ≈90 断言全绿），数字均为 2026-08-28 当日本机真 AI 模式实测，是进入实战印证前最硬的可信度背书。衔接句：「指标都答得上来，再看真实战例里的价值映射。」
