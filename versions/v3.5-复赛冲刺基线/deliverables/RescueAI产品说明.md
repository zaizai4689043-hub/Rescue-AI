# RescueAI · AI地震救援平台 产品说明

> Physical AI for Earthquake Rescue —— 从地震预警信号到无人机空中救援的完整闭环。
>
> 本文档以已开发完成的产品实现为准，所述功能、数据与指标均经源码与运行验证。

---

## 一、产品核心解决的问题与目标用户

### 1.1 核心问题：震后黄金 72 小时的「信息黑洞」

地震救援存活率随时间急剧下降：**24 小时约 80% → 48 小时约 50% → 72 小时约 30%**。而恰恰在最宝贵的时间窗口内，信息供给是断裂的：

| 痛点 | 事实依据（2025 年缅甸地震实测） |
|---|---|
| **官方通报沉默期** | 震后约 5 分钟社媒已在流传伤亡信息，官方首报 19:15 才发布——沉默约 5 小时 |
| **灾情信息碎片化** | 53,340 条中文微博散落呼救、损毁、谣言，无结构化、无坐标、无优先级 |
| **无系统化决策答案** | 「哪里最严重？先救哪里？路怎么走？」——三个指挥核心问题均无现成答案 |

一个耐人寻味的细节：**首条涉震微博早于主震发震时刻 1 分 46 秒**——社交媒体是比仪器台网更快的「第一传感器」，但今天没有任何系统把它接进救援指挥链路。

RescueAI 的思路是：**让 AI 把社媒上的每一句呼救，变成地图上的坐标和优先级。**

### 1.2 目标用户

| 用户 | 使用场景 |
|---|---|
| **各级应急救援指挥部门 / 应急管理者**（主用户） | 震后第一时间生成灾情简报、划定区域优先级、辅助调度决策 |
| **一线救援队** | 获取目标坐标、安全进入路径、被困者状态与营救队列 |
| **人道机构与公益组织** | 物资缺口估算、援助明细对齐、公益协作清单 |

### 1.3 定位声明

RescueAI 是**辅助决策系统，不替代专业救援判断**；所有预测与估算均展示不确定性区间；数据经授权脱敏合规处理。

> 「AI 不替代救援者，它做的只是把时间抢回来。」

## 二、核心功能与应用场景

产品主体为单文件指挥中心版（`代码1.2-ai.html` + 本地代理 `ai_proxy.py`），支持四种运行模式：主模式（真实 AI）、历史重演（`?replay=1`）、纯仿真保险丝（`?sim=1`）、二者叠加。

| # | 功能模块 | 能力要点 | 典型应用场景 |
|---|---|---|---|
| 1 | **历史重演剧场** | 缅甸 M7.7 地震（CENC 7.9 / USGS Mw7.7 双口径）真实时间轴 ×90 压缩，四段叙事：监测告警 → 社情爆发 → 伤亡浮现 → 救援展开，全程约 67 小时压至约 45.8 分钟，30 个真实事件流 | 答辩、路演与复盘推演中，让决策者亲历「信息黑洞」如何在真实事件中被逐段填平 |
| 2 | **双源灾情感知** | 仪器侧：ICL 地震预警通道（烈度 1–5 映射上色）；社情侧：微博瀑布流 + NER 高亮（地名黄框 / 损毁关键词红框），severity≥5 的伤亡帖自动标记「已转入处置」 | 震后数分钟内同时盯着台网与社媒两条流，自动把高严重度呼救帖送进搜索优先级队列 |
| 3 | **AI 灾情简报** | qwen3.8-max · 应急管理部通报风格，≤200 字，覆盖震中位置 / 受损范围 / 损毁类型 / 重点区域 / 被困规模预估；样例实测生成耗时 1.8s、198 字 | 官方通报沉默期内，指挥员先拿到一份可流转的「第 1 号」灾情简报 |
| 4 | **AI 决策助手** | 五区分数表 + 8 个历史救援案例（汶川 / 玉树 / 芦山 / 鲁甸 / 泸定 / 尼泊尔 / 土叙 / 缅甸）匹配，≤150 字建议 | 面对陌生灾区，参照历史上最相似震情的策略与教训下第一波决策 |
| 5 | **营救优先级中心** | 两级结构：区域 P0–P3（社情驱动，开屏即现，不依赖无人机）+ 个人营救队列（无人机定位后生成，含心率、埋深、AI 决策理由、五阶段进度、派遣按钮） | 同时有 5 个区域告急时，评分公式（严重度 × 帖量对数 × 时效 × 资源缺口）告诉你先打哪一个 |
| 6 | **数字孪生地图** | Canvas 渲染，曼德勒真实卫星影像底图，6 图层：热成像信号 / 激光雷达点云 / 结构安全 / 设备定位 / 安全进入路径 / **社情感知（灾情热力图）**——单地图架构，热力图为并入主地图的图层而非独立面板 | 指挥员在一张图上同时看到社情热点、被困信号与安全路径 |
| 7 | **结构安全分析** | Qwen-VL 多模态照片研判，输出图纸匹配度 / 承重构件识别数 / 稳定生存空间 / 结构稳定度四值 + 损毁四档 + 置信度，支持换图重测（真实震后照片） | 破拆前先用 AI 判一遍废墟稳定性，避免二次坍塌伤及救援人员 |
| 8 | **沙盘推演五阶段救援** | 开进 → 现场勘察 → 语音联络 → 破拆支护 → 医疗移交；起飞扫描点亮被困者、AI 自动生成优先级理由、喊话安抚（Web Speech 合成播报） | 基于真实数据的数字孪生推演沙盘：社情 / 余震 / 伤亡时间线为真实数据，人员与设备为推演样本 |
| 9 | **余震联动** | 强余震（M≥5）自动暂停破拆支护；AI 余震指挥参谋给出 ≤80 字应对建议；震屏 + 结构完整度下降 + 被困者心率波动 | 正在破拆时突发 M6.7 余震（主震后 11.2 分钟真实发生），系统先停手再评估 |
| 10 | **空中救援** | 物资投送：运输机投送降落伞货箱，目标 = 优先级引擎第一名区域，单架次 ≈200kg（帐篷×2 / 毛巾被×10 / 赈济家庭包×4 / 折叠床×1）；航拍研判：无人机巡航 TOP3 热点，qwen3.7-plus 回传 ≤120 字航空侦察研判 | 道路中断时先空投急需物资，航拍图替代人力抵近侦察 |
| 11 | **物资需求估算** | 15 类物资动态估算，三阶段切换（紧急搜救 0–24h / 医疗安置 24–72h / 恢复安置 72h+），表格含「微博信号数」列（真实需求类别聚合，无信号如实计 0） | 人道机构按缺口清单组织第二批援助，避免「帐篷过剩、血袋告急」式错配 |

> 另：Vue 3 + FastAPI 标准平台版（多用户、权限、数据库）为平台化框架（建设中），本文档以指挥中心版为主体。

## 三、技术实现路径

### 3.1 端到端七步闭环架构

```
① 预警信号 / 地震检测 → ② 微博社媒监测 → ③ 噪声过滤（去重→辟谣→机器人识别→地理围栏）
→ ④ NLP 实体抽取（NER）→ ⑤ 社情热力图 → ⑥ 优先级引擎 → ⑦ 无人机救援调度
```

检测到任何地震信号即立即启动社媒监测，七步在统一指挥界面上逐段点亮、全程可追溯。

### 3.2 AI 层

| 项 | 实现 |
|---|---|
| 文本模型 | qwen3.8-max（简报 / 决策助手 / 优先级理由 / 余震参谋 / 喊话），超时 5s |
| 视觉模型 | qwen3.7-plus（结构安全研判 / 航拍研判），超时 20s |
| 本地代理 | `ai_proxy.py`（仅 Python 标准库，端口 8010，仅回环访问）：转发 DashScope 兼容接口，参数白名单 + 默认注入 `enable_thinking:false` 提速；60s TTL / 200 条内存缓存（payload sha256 为键）；任何异常一律返回结构化 fallback，前端无缝走预录兜底 |

### 3.3 可靠性设计（断网可演示）

- **真实 Key 预录 fallback 兜底**：7 类兜底文案（结构研判 / 优先级理由 / 余震参谋 / 喊话 / 简报 / 决策助手 / 航拍研判）由真实 API Key 预跑录制而非手写，保证断网时口径与真实 AI 一致；
- **warmup 预热**：页面加载时并发预跑写入缓存，现场点击秒回，中途断网也有结果；
- **`?sim=1` 零请求模拟模式**：全部 AI 调用走缓存 / 预录，震情用离线样例、预警用内嵌快照，零外网依赖。

### 3.4 数据管线

- **社情语料**：公开学术数据集《The Weibo data text about the Myanmar earthquake in 2025》，**53,340 条中文微博真实语料**（72% 集中于震后当天），经 qwen-plus LLM 标注管线（去重→辟谣→机器人识别→地理围栏四层过滤）产出 52 条精选，漏斗：**53,340 → 40,595 → 9,617 → 65 AI 甄别 → 52 精选**；昵称 / UID 整列丢弃、@提及与短链剥离、post_id 不可逆哈希，全程匿名化合规；
- **震情数据**：USGS ComCat 余震目录（主震后 0–100min 实测 10 条）、ICL 预警接口三级降级（上游 → 本地快照 → 内嵌样例）；
- **视觉素材**：曼德勒震后真实倒塌建筑照片（2 张，可换图重测）+ 真实卫星影像底图。

### 3.5 可视化与扩展

- **可视化**：单文件 HTML + Canvas 2D + 内嵌 SVG，**零第三方图表库、零构建**，数据全部内嵌（零 fetch），双击即可运行；
- **真机预留接口**：`POST /drone/telemetry` 桩已预留大疆 Cloud API / MAVLink 转发位，真机接入即插即用。

## 四、技术创新点与差异化优势

### 4.1 端到端救援指挥闭环

市场调研显示：UNOSAT / SKAI 止步于损毁评估图（数周时效），ICL 止步于预警通道，商业遥感公司只做保险理赔定损。**现有产品重「报」，RescueAI 重「判」**——是唯一从预警信号一路贯通到无人机营救调度的决策闭环。

### 4.2 中文社媒灾情 NER + 热力图

CrisisNLP 等主流基准均为英文，中文微博灾情 NER 业务化落地罕见。本产品基于 5.3 万条真实中文微博跑通「NER 抽取 → 地名聚合 → 热力图层 → 优先级引擎」全链路，地名 GPE 提取率对标论文基准 **91%**（arXiv:2503.16509）。

### 4.3 真实事件重演 + 数字孪生推演双模式

对标 UNOSAT 数周交付，本产品讲「分钟级」故事：历史重演剧场 ×90 压缩复现真实 67 小时，沙盘推演实测起飞→首次发现仅 **7.8 秒**、派遣→救出约 **35.5 秒**。真实数据与推演样本边界清晰（8 名被困者均为数字孪生推演样本）。

### 4.4 余震驱动的动态决策

余震不是背景板而是决策变量：强余震自动暂停破拆支护，AI 余震参谋实时给出应对建议——救援节奏与地震序列联动，而非一次性静态方案。

### 4.5 可信 AI 设计

- **证据链**：每条优先级结论附原始微博 / 官方通报证据，无匹配帖时如实显示「社情信号 ×0 · 依据官方通报」，不编造；
- **诚实计量**：无信号如实计 0；伤亡数字采用致哀口径（「以下数字来自官方通报，谨以致哀」）；
- **LIVE / SIM 双轨**：真实 AI 与模拟模式明确标注，演示口径永不失真。

### 4.6 工程可靠性：三级降级

**真实 AI → 预录兜底 → 离线快照**，断网、断 Key、断上游均可完整演示，且口径与真实模式一致——这是「随时可上讲台」的底气。
