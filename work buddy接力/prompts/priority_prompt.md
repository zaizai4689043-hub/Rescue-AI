# 优先级排序提示词

## 优先级决策理由生成提示词

```
你是地震救援指挥官。以下是一名被困人员/灾情热点的信息：

{trapped_person_or_hotspot_data}

请给出不超过 40 字的中文优先级决策理由。

## 要求
1. 说明为何该优先级（数据依据）
2. 建议携带装备
3. 不超过 40 字
4. 只返回理由文本，不要其他文字

## 示例
- "P0：3条呼救信号，预估5人被困，房屋倒塌严重，建议携带生命探测仪和破拆设备"
- "P1：帖文12条但无呼救，道路中断需直升机投送，建议携搜救犬"
- "P2：震感反馈为主，暂无伤亡报告，持续监测"
```

## 优先级评分规则

```
## 评分公式

base_score = 1 - exp(-urgency_score / 10)
  urgency_score = post_count × avg_severity × avg_credibility

distress_boost = min(1.5, 1.0 + distress_count × 0.2)

penalty = 1.0
  - 已有救援队在前 → penalty × 0.6
  - 道路不可达 → penalty × 0.3
  - 超 72h → penalty × 0.5

final_score = base_score × distress_boost × penalty

## 等级映射

P0: final_score >= 0.8  → 立即派遣
P1: 0.5 <= final_score < 0.8 → 优先派遣
P2: 0.3 <= final_score < 0.5 → 常规搜救
P3: final_score < 0.3 → 持续监测

## 资源约束考量

1. **已有救援队在前**：该区域已有救援力量 → 降级
   - 不意味着不需要救援，而是不需要新增力量
   - 除非呼救信号激增（>5条新增）

2. **道路不可达**：
   - 需评估直升机投送可行性
   - 标注"需空运"而非直接排除
   - penalty=0.3 而非 0（仍然需要救援，只是难度大）

3. **超时 72h**：
   - 生存率从 30% 降至 <10%
   - 降级但不放弃（奇迹仍有发生）
   - penalty=0.5 而非 0
```

## 动态刷新策略

```
## 何时刷新优先级

1. **定时刷新**：每 15 分钟自动刷新一次
2. **事件触发**：
   - 新增呼救信号 → 该区域立即刷新
   - 新增大量帖文（>10条/5min）→ 该区域刷新
   - 道路状态变更 → 影响区域刷新
   - 救援队到达 → 该区域降级

## AI 理由生成策略

- 只为 P0/P1 级别生成 AI 理由（减少 API 调用）
- P2/P3 使用模板理由
- 缓存 60 秒，避免重复调用
```
